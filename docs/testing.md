# Testing AnglePlates

## Project and generator helpers

The nonpackable .NET 10 executable uses TUnit 1.65.0, Roslyn 4.14.0, Verify.TUnit 31.27.0, Verify.SourceGenerators 2.5.0. `global.json` selects Microsoft.Testing.Platform. Run the existing suite with `dotnet test --solution AnglePlates.slnx --no-build --no-restore` after restoring and building. Focused regressions now cover ordinary brackets, empty/unclosed blocks, trim flags, directive matching and line consumption, duplicate and invalid directive values with their locations, `#using` emission and name collisions, invalid-template isolation, source-name stability, compiler-reported duplicate types, invariant-culture formatting of C# variables, `NullVariable` substitution for null C# variables of every type (including `dynamic` and objects whose `ToString` returns `null`), repeated C# variables in one block, compiler errors for unconvertible and stray C# variables such as `[[1, 2]]` and their `#line` locations in the template, `#line` locations for multi-line C# blocks, template paths with quotes or line breaks, which can't appear in a `#line` directive and are escaped in the generated class documentation, escaped openers (backslash runs of one to four, trim markers, both line endings, and JavaScript, Bash, TOML, regex, and Markdown samples), and pooled-buffer ownership on success and failure. MSBuild option regressions cover untagged and unrecognized `AdditionalFiles`, which are ignored without being read, case-insensitive `AnglePlate` metadata values, discovered files without directives that are skipped, explicit files without directives that report `SLAP008` at the first line, `AnglePlateBaseAccessModifier` values that are missing, empty, padded, or differently cased, invalid values that report `SLAP009` and generate nothing, template names relative to Windows, UNC, and Unix project folders (including paths outside the folder, case-only prefix differences, and full-path fallbacks), and an edited untagged file that doesn't rerun the template steps. Incremental regressions in `TemplateGeneratorTests.Incremental.cs` cover editing one of two templates, an unrelated consumer source change, adding and removing a template, changing `AnglePlateBaseAccessModifier` to another valid value, to an invalid one, and back, reporting a cached template's diagnostics again, editing one of two identical templates without renumbering their hint names, adding and dropping the UTF-8 base class when a template's targets change, and reusing an unchanged template's generated `SourceText`.

[GeneratorTestHelper](../tests/AnglePlates.Tests/Infrastructure/GeneratorTestHelper.cs) creates C# 11 consumer compilations with explicit imports and .NET 10 host references. Supply different references and language versions for compatibility cases; the default does not qualify older consumer frameworks. Supply in-memory `TemplateAdditionalText` instances and `TestAnalyzerConfigOptionsProvider` for global or per-file options.

The generator only reads additional files that carry the `build_metadata.AdditionalFiles.AnglePlate` value that template discovery adds. To keep ordinary tests free of per-file options, `TestAnalyzerConfigOptionsProvider` tags any additional file without per-file options as `Discovered`, even when a test supplies only global options. Pass `TemplateAdditionalText.Explicit` as the `anglePlate` argument of `TemplateAdditionalText` or `RenderingTestHelper.Template` to make a file explicit, or `null` to leave it untagged. Per-file options replace the default tag entirely. `TemplateAdditionalText.GetTextCount` counts `GetText` calls, so a test can check that the generator never read a file. The pipeline steps that filter and read files are tracked as `AnglePlateFiles` and `TemplateFiles`. `TemplateResults` parses and transpiles each template, `NeedsUtf8` decides whether the UTF-8 base class is generated, and `DuplicateTemplates` collects the sources of templates whose hint names collide.

`RenderingTestHelper.Template` wraps a body in the standard directives with a `string` model, and `RenderingTestHelper.Render` runs both renderers with an optional `NullVariable`. Use casts in the template body, such as `[[ (int?)null ]]`, to test other C# variable types.

`Run` executes the real generator, rejects generator exceptions and emits the resulting compilation before returning its driver, compilation and run result. Pass only templates to use the default compilation and driver, or pass your own when a test needs extra consumer sources, options, or a rerun. Successful cases permit no compiler errors. Negative compilation cases must supply exact `ExpectedCompilerDiagnostic` values, including invariant messages and locations; do not derive expected values from the actual diagnostics. Each value holds both the generated-code location and the `#line`-mapped template path and span. When an expected value omits the mapped location, it defaults to the generated location, which is what errors outside a mapping report. Assert generator diagnostics and locations separately from compiler errors. No broad error-acceptance switch is provided.

Use the returned driver with the original consumer compilation for reruns; update its additional texts or options through Roslyn driver methods. Tracked incremental steps are enabled. Assert both outputs and relevant reuse reasons when adding incremental tests. Roslyn 4.14 parses a new `SyntaxTree` for every generated source on each run, even when the output step is cached, so check reuse through `SourceText` identity and `TrackedOutputSteps` instead of tree identity. Do not reuse a compilation containing previously generated trees as the next input.

`GeneratedAssembly.Load` emits the validated output in memory with a unique assembly identity, then loads it in a collectible context. Dispose the returned handle and release reflected objects when finished. The parser regressions execute both renderers and assert exact characters and bytes. Rendering regressions use counting pools, custom encoders, and throwing writers to check buffer identity, matched returns, overflow-safe requests, Unicode chunk boundaries, and writer ownership. Unsafe code is enabled only in the test project because custom `TextEncoder` implementations must override pointer-based abstract members.

## Snapshot review

[ModuleInitializer](../tests/AnglePlates.Tests/Infrastructure/ModuleInitializer.cs) initializes Verify.SourceGenerators once and directs Verify.TUnit artifacts into [Snapshots](../tests/AnglePlates.Tests/Snapshots). For snapshot tests, call `Run`, which validates the compilation, assert any diagnostics, and then await `Verifier.Verify(result.RunResult)`.

Store reviewed `*.g.verified.cs` and `*.verified.txt` files in `Snapshots`; generated C# snapshots are excluded from compilation. Existing `.gitattributes` and `.editorconfig` settings preserve LF snapshot output while normal source files use CRLF. Unreviewed `*.received.*` output is ignored by Git.

On a snapshot failure, inspect every generated-source and diagnostic diff, including support types and both renderers. Accept only intentional changes using the comparison tool or by replacing the corresponding verified file after review, then rerun the affected cases. Never enable automatic acceptance. Parameterized cases need distinct Verify parameter naming. Snapshot equality does not replace runtime assertions. Reviewed snapshots cover both renderer sources (including an emitted `#using` import and `#line` mappings), a text renderer with escaped openers merged into one literal, their generated support types, the unclosed-block diagnostic, and the duplicate-directive and invalid-value diagnostics.

Coverage is run by the maintainer in Visual Studio 2026. No repository coverage scripts, configuration or CI gate are required.
