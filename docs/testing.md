# Testing AnglePlates

## Project and generator helpers

The nonpackable .NET 10 executable uses TUnit 1.65.0, Roslyn 4.14.0, Verify.TUnit 31.27.0, Verify.SourceGenerators 2.5.0. `global.json` selects Microsoft.Testing.Platform. Run the existing suite with `dotnet test --solution AnglePlates.slnx --no-build --no-restore` after restoring and building. Focused regressions now cover ordinary brackets, empty/unclosed blocks, trim flags, directive matching and line consumption, duplicate and invalid directive values with their locations, `#using` emission and name collisions, invalid-template isolation, source-name stability, compiler-reported duplicate types, invariant-culture formatting of C# variables, `NullVariable` substitution for null C# variables of every type (including `dynamic` and objects whose `ToString` returns `null`), repeated C# variables in one block, compiler errors for unconvertible and stray C# variables such as `[[1, 2]]` and their `#line` locations in the template, `#line` locations for multi-line C# blocks, template paths with quotes or line breaks, which can't appear in a `#line` directive and are escaped in the generated class documentation, escaped openers (backslash runs of one to four, trim markers, both line endings, and JavaScript, Bash, TOML, regex, and Markdown samples), and pooled-buffer ownership on success and failure. MSBuild option regressions cover untagged and unrecognized `AdditionalFiles`, which are ignored without being read, case-insensitive `AnglePlate` metadata values, discovered files without directives that are skipped, explicit files without directives that report `SLAP008` at the first line, `AnglePlateBaseAccessModifier` values that are missing, empty, padded, or differently cased, invalid values that report `SLAP009` and generate nothing, template names relative to Windows, UNC, and Unix project folders (including paths outside the folder, case-only prefix differences, and full-path fallbacks), and an edited untagged file that doesn't rerun the template steps. Accessibility regressions in `TemplateGeneratorTests.Accessibility.cs` cover the default `internal` support types and template classes, the `CS0060` and `CS0051` errors from a `#access public` template on `internal` support types, and two-assembly compilations built with `CreateCompilation`'s `references` and `assemblyName`: a consumer with its own template that renders a referenced library's public template and gets only `CS0436` warnings, the `CS1503` error when that consumer passes its own `TemplateOptions` to the library's template, and the `CS0433` error in a consumer without AnglePlates that references two such libraries. `GeneratedAssembly.Load` accepts referenced assembly images and loads them into the same context so the consumer can run them. Incremental regressions in `TemplateGeneratorTests.Incremental.cs` cover editing one of two templates, an unrelated consumer source change, adding and removing a template, changing `AnglePlateBaseAccessModifier` to another valid value, to an invalid one, and back, reporting a cached template's diagnostics again, editing one of two identical templates without renumbering their hint names, a template's generation target changing while the support types keep their cached `SourceText`, raising the C# version from 10 to 11 so cached templates generate, and reusing an unchanged template's generated `SourceText`. Compatibility regressions cover `SLAP010` for C# 9 and 10, with nothing generated and no other diagnostic, generation and rendering at C# 11, 12, `Latest`, and `Preview`, and `SLAP010` reported together with `SLAP009`. Every project gets all three support types, whatever its templates generate.

[GeneratorTestHelper](../tests/AnglePlates.Tests/Infrastructure/GeneratorTestHelper.cs) creates C# 11 consumer compilations with explicit imports and .NET 10 host references. Supply different references and language versions for compatibility cases; the default does not qualify older consumer frameworks. Supply in-memory `TemplateAdditionalText` instances and `TestAnalyzerConfigOptionsProvider` for global or per-file options.

The generator only reads additional files that carry the `build_metadata.AdditionalFiles.AnglePlate` value that template discovery adds. To keep ordinary tests free of per-file options, `TestAnalyzerConfigOptionsProvider` tags any additional file without per-file options as `Discovered`, even when a test supplies only global options. Pass `TemplateAdditionalText.Explicit` as the `anglePlate` argument of `TemplateAdditionalText` or `RenderingTestHelper.Template` to make a file explicit, or `null` to leave it untagged. Per-file options replace the default tag entirely. `TemplateAdditionalText.GetTextCount` counts `GetText` calls, so a test can check that the generator never read a file. The pipeline steps that filter and read files are tracked as `AnglePlateFiles` and `TemplateFiles`. `TemplateResults` parses and transpiles each template, and `DuplicateTemplates` collects the sources of templates whose hint names collide.

`RenderingTestHelper.Template` wraps a body in the standard directives with a `string` model, and `RenderingTestHelper.Render` runs both renderers with an optional `NullVariable`. It also renders the UTF-8 class with `RenderAsync` to a `Pipe` without backpressure and fails if those bytes differ from `Render`, so every rendering case checks `RenderAsync` too. `RenderingTestHelper.RenderAsync` returns the `ValueTask` for tests that pass their own `PipeWriter` or cancellation token. Use casts in the template body, such as `[[ (int?)null ]]`, to test other C# variable types.

`Run` executes the real generator, rejects generator exceptions and emits the resulting compilation before returning its driver, compilation and run result. Pass only templates to use the default compilation and driver, or pass your own when a test needs extra consumer sources, options, or a rerun. Successful cases permit no compiler errors. Negative compilation cases must supply exact `ExpectedCompilerDiagnostic` values, including invariant messages and locations; do not derive expected values from the actual diagnostics. Each value holds both the generated-code location and the `#line`-mapped template path and span. When an expected value omits the mapped location, it defaults to the generated location, which is what errors outside a mapping report. Assert generator diagnostics and locations separately from compiler errors. No broad error-acceptance switch is provided.

Use the returned driver with the original consumer compilation for reruns; update its additional texts or options through Roslyn driver methods. Tracked incremental steps are enabled. Assert both outputs and relevant reuse reasons when adding incremental tests. Roslyn 4.14 parses a new `SyntaxTree` for every generated source on each run, even when the output step is cached, so check reuse through `SourceText` identity and `TrackedOutputSteps` instead of tree identity. Do not reuse a compilation containing previously generated trees as the next input.

`GeneratedAssembly.Load` emits the validated output in memory with a unique assembly identity, then loads it in a collectible context. Dispose the returned handle and release reflected objects when finished. The parser regressions execute both renderers and assert exact characters and bytes. Rendering regressions use counting pools, custom encoders, and throwing writers to check buffer identity, matched returns, overflow-safe requests, Unicode chunk boundaries, and writer ownership. Unsafe code is enabled only in the test project because custom `TextEncoder` implementations must override pointer-based abstract members.

## Snapshot review

[ModuleInitializer](../tests/AnglePlates.Tests/Infrastructure/ModuleInitializer.cs) initializes Verify.SourceGenerators once and directs Verify.TUnit artifacts into [Snapshots](../tests/AnglePlates.Tests/Snapshots). For snapshot tests, call `Run`, which validates the compilation, assert any diagnostics, and then await `Verifier.Verify(result.RunResult)`.

Store reviewed `*.g.verified.cs` and `*.verified.txt` files in `Snapshots`; generated C# snapshots are excluded from compilation. Existing `.gitattributes` and `.editorconfig` settings preserve LF snapshot output while normal source files use CRLF. Unreviewed `*.received.*` output is ignored by Git.

On a snapshot failure, inspect every generated-source and diagnostic diff, including support types and both renderers. Accept only intentional changes using the comparison tool or by replacing the corresponding verified file after review, then rerun the affected cases. Never enable automatic acceptance. Parameterized cases need distinct Verify parameter naming. Snapshot equality does not replace runtime assertions. Reviewed snapshots cover both renderer sources (including an emitted `#using` import and `#line` mappings), a UTF-8 `RenderAsync` with its flush checks, a text renderer with escaped openers merged into one literal, their generated support types, the unclosed-block diagnostic, and the duplicate-directive and invalid-value diagnostics.

## Streaming `RenderAsync`

`TemplateGeneratorTests.RenderAsync.cs` covers the UTF-8 `RenderAsync` method. [CountingPipeWriter](../tests/AnglePlates.Tests/Infrastructure/CountingPipeWriter.cs) records the bytes written before each flush. When it doesn't report unflushed bytes, every flush check flushes, so its flush count is the number of checks plus the final flush; the tests use that to show checks only at the first write after each C# block, through brace-less and nested C#, comments and empty blocks between a block and its write, child templates rendered from a loop, and blocks and literals that end on a line break. With unflushed bytes reported, the tests check the 16 KB threshold and a small page that flushes only at the end. `OnFlush` lets a test cancel the token mid-render or return a flush result that reports a completed reader or a canceled flush. Other cases cover a token canceled before the render, a real `Pipe` whose reader already completed, and a real `Pipe` whose backpressure holds the render until the reader catches up. A reviewed snapshot shows the generated `RenderAsync`, and compiler-error tests pin the template locations for a ref struct local in a C# block under C# 11 (`CS9058`) and C# 13 (`CS4007`), an await inside `lock` (`CS1996`) and `unsafe` (`CS4004`), and ordinary errors that both render methods report at the same location.

## Package consumers

The test project loads the generator from source, so it can't show that the packed analyzer works. `eng/validate-package.ps1` installs a freshly packed version into isolated consumers outside the solution; [Validating the package](development.md#validating-the-package) explains how to run it, and the [package validation README](../tests/AnglePlates.PackageTests/README.md) lists what each consumer checks. Every consumer targets `net10.0` with C# 11, so together they cover the compatibility floor, and each one now renders with `RenderAsync` and checks the bytes.

The `NativeAot` consumer turns on `IsAotCompatible` and `PublishAot` with `TreatWarningsAsErrors`, so any trim or AOT analyzer warning fails its build or publish. The script runs it twice: with `dotnet run` under the JIT, then as a native executable published for the machine's runtime identifier. Both runs compare text and UTF-8 output from `Render` and `RenderAsync` with the same hard-coded bytes. The script stops before running anything if the native toolchain is missing, unless you pass `-SkipNativeAot`.

Coverage is run by the maintainer in Visual Studio 2026. No repository coverage scripts, configuration or CI gate are required.
