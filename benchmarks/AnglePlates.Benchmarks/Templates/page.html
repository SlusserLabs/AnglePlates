Getting started

Templates compile into ordinary C# classes when your project builds. There is nothing to parse at run time, no reflection, and no runtime package to deploy. Literal text like this paragraph is stored in the assembly and written straight to the output.

Each template gets a text renderer for a TextWriter and a UTF-8 renderer for an IBufferWriter<byte>, so you can render to a console, a file, or an HTTP response.

Why literal-heavy pages matter

Most real pages are mostly markup. Navigation, layout, scripts, and boilerplate dwarf the handful of values a template fills in. A renderer that handles literal text well handles most of the page well.

  • Headers and footers repeat on every page.
  • Inline styles and scripts are large and never change.
  • Forms carry labels, hints, and validation messages.
  • Tables of contents and breadcrumbs are mostly links.

Frequently asked questions

Does it support layouts?
A template is a class, so a C# block can render another template into the same writer.
Is output encoded?
C# variables are HTML-encoded by default. Literal text is written exactly as it appears.
Can I stream?
Yes. Output goes straight to the writer you pass in, and RenderAsync flushes a pipe as it renders.
