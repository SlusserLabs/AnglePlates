# Package consumer validation

This .NET 10 executable is outside `AnglePlates.slnx`. It consumes only a package reference and the framework; it has no generator project reference or source-tree imports. Its project file is written the way the README tells consumers to write theirs: relative paths, `PrivateAssets` on the package reference, and `Include` and `Remove` operations on `AnglePlate` items.

It checks:

- a discovered template in `Templates`, an extra folder added with `Include`, and an explicit template outside both
- a template that's both discovered and listed explicitly by its full path, which must generate one class and count as explicit
- a `Remove` that drops a deliberately invalid template from the default item
- `PublicAPI.Shipped.txt` and `README.md` added as plain `AdditionalFiles`, plus a `README.md` and an empty file inside `Templates`, all of which must leave the build clean
- the generated editorconfig, where each template must carry one `AnglePlate` value of `Discovered` or `Explicit` and every other additional file must stay untagged
- the default `internal` accessibility of the support types and templates, analyzer loading, exact encoded text, UTF-8, and `RenderAsync` output, and the `NullVariable` substitute for a null `int?` model
- a template saved as UTF-8 with a byte order mark and non-ASCII literal text, whose text and UTF-8 output must keep that text and drop the mark

`PackageValidator` also checks package metadata and contents, including the development-dependency flag, analyzer/runtime separation, XML documentation, reproducible-build metadata, matching portable PDB identity/checksum, and Source Link URLs against the repository commit recorded in the package. When the script passes `-ExpectedCommit`, that recorded commit has to match it. The description and tags can't be empty. `ReadmeValidator` reads the packed README the way nuget.org shows it: every link has to be an absolute `https://` URL or a `#anchor`, every image has to come from a host on nuget.org's trusted list, and no line can start with `# TODO` or `TODO:`. `IconValidator` requires `icon.png` to be a square PNG between 128 and 512 px and no bigger than 100 KB. `ConsumerAssetsValidator` reads this project's own `project.assets.json` and fails if the restore gave the AnglePlates entry anything besides the props and targets under `build/` (analyzers aren't listed there), so a stray `lib/` or `ref/` file shows up as a `compile` or `runtime` asset and fails the run.

The program needs the package arguments and fails with a usage message without them: `--package <path.nupkg> --version <version>`, then `--symbols <path.snupkg>`, or `--no-symbols` for a package restored from a feed, and optionally `--expected-commit <sha>`. The script passes them for you.

Cases that need their own project layout live in [tests/AnglePlates.PackageConsumers](../AnglePlates.PackageConsumers). Each one follows the same rules, checks its own results, and exits nonzero on failure. A class that must not exist is looked up by name through reflection, because code that names it wouldn't compile. This table lists every consumer the script runs, and other docs link here instead of repeating it.

Most consumers reference the package with the one-line form, `<PackageReference Include="SlusserLabs.AnglePlates" Version="..." PrivateAssets="all" />`. `AspNetCore` keeps the multi-line reference that `dotnet package add` writes, and `NoPrivateAssets` leaves `PrivateAssets` out on purpose.

| Consumer | What it checks |
| --- | --- |
| `AnglePlates.PackageTests` | This project. It checks the package layout and metadata, the consumer's assets, the discovery tags, the fixtures above, and the byte order mark template. |
| `RemoveDefault` | A `Remove` in the project file drops the default folder, while an explicit `Include` still generates. The script then edits `Emails/extra.html` and rebuilds, and the app must render the new text. Then it deletes that file and rebuilds, and the app must find no `ExtraTextTemplate` class. |
| `DirectoryBuildPropsRemove` | `EnableDefaultAnglePlateItems` set to `false` in `Directory.Build.props` turns off the default folder. A `Remove` in the same file does nothing, because it runs before the project file adds the template it names, so that template still renders. |
| `DirectoryBuildTargetsRemove` | A `Remove` in `Directory.Build.targets` drops the default folder. |
| `LibraryChain` | An app referencing a library that uses AnglePlates gets no `AnglePlate` items or classes from its own `Templates` folder, but still renders the library's public template, which needs public support types in the library. |
| `SharedTemplates` | An app and the library it references both use AnglePlates, and the library's template and support types are public. The app builds with warnings as errors except `CS0436`, so the support-type collision the README describes is the only warning, and it renders both projects' templates with `Render` and `RenderAsync`. |
| `PackagedLibrary` | An app gets a library with a public template as a NuGet package, packed by the script into a folder of its own. AnglePlates isn't a dependency of that package, so the app gets no `AnglePlate` items, no generator, and no classes from its own `Templates` folder, but still renders the packaged template. |
| `NoPrivateAssets` | A library references AnglePlates without `PrivateAssets`, and an app reaches it through a `ProjectReference` and has its own `Templates` folder. The app gets no `AnglePlate` items and no template classes, because the build files stay in the library. The generator does reach the app, though, and adds `internal` support types there, which collide with the library's public ones as `CS0436` warnings. The consumer pins that leak, so a change to it shows up here. |
| `CentralPackageManagement` | `ManagePackageVersionsCentrally` with a `GlobalPackageReference` in `Directory.Packages.props` and no reference in the project file. The default folder generates and renders. |
| `DefaultNames` | Templates with no `#type` or `#namespace` in nested folders get classes named after the file, in `RootNamespace` plus the folders. An `#encode none` template renders unencoded through `Default`, and both use `RenderToString`. |
| `ScannerParity` | C# variables and C# blocks end where the scanner says under the consumer's own compiler: closers inside strings, character literals, raw and interpolated strings, and `/* */` comments are skipped, brackets balance, `//` comments and `#if` lines end at their first closer, and a C# variable can end in a `//` comment. Text and UTF-8 output must match exactly. |
| `AspNetCore` | A Kestrel app on a loopback port serves UTF-8 templates with `RenderAsync` and `Render` to the response `PipeWriter`. An `HttpClient` checks the exact bytes of a small page and of a large page that passes the flush threshold and Kestrel's response buffer many times, then disconnects from an endless page and checks that the render stops with an `OperationCanceledException`. It also compiles a copy of the README's ASP.NET Core example with the README's greeting template. |
| `UnsupportedFramework` | A `net8.0` app must fail to build with exactly the errors in its `ExpectedErrors.txt`: `CS0234`, because `System.IO.Pipelines` isn't part of .NET 8, and nothing else. A new error means the generated code started using a newer API, which reopens the `SLAP012` decision in [Supported frameworks](../../docs/development.md#supported-frameworks). |
| `BuildErrors` | One small project per case, and each must fail to build with every line in its `ExpectedErrors.txt`: `SLAP001`, `SLAP002`, `SLAP004`, `SLAP005`, `SLAP008`, `SLAP009` (from `-p:AnglePlateBaseAccessModifier=private`), `SLAP010` (from `-p:LangVersion=10`), `SLAP011` as an error under `-warnaserror`, `CS0111` and `CS0102` for two templates that declare the same class, and `CS0103` inside a C# block at `Templates/bad.html(5,4)`. Extra build arguments come from the case's `BuildArguments.txt`. |
| `NativeAot` | Text and UTF-8 classes, `Render`, `RenderAsync`, and `RenderToString`, a public and an internal template, a child template rendered from a C# block through a `#using`, a non-ASCII literal, a value over 32K characters, and C# variables that are an enum, a `[Flags]` enum, an `int?`, a `decimal`, a `double`, a `DateTime`, a `DateTimeOffset`, a `Guid`, and an `object` whose `ToString` returns `null`. Another template renders with `TemplateOptions.Html`, `Unencoded`, `JavaScript`, and a custom `NullVariable`. It builds with `IsAotCompatible`, `PublishAot`, `GenerateDocumentationFile`, and warnings as errors, and the script checks that `EnableTrimAnalyzer`, `EnableAotAnalyzer`, and `IlcTreatWarningsAsErrors` all come out `true`. It runs under the JIT, then publishes and runs as a native executable, and both runs check the same exact text and bytes. Last, the AOT canary publishes it with `-p:AotCanary=true`, which adds a template with a `dynamic` C# variable, and that publish must fail with `IL2026` or `IL3050`. |

The expected-error files use paths relative to the project folder with `/` separators, as in `Templates/bad.html(5,4): error CS0103: ...`. Before comparing, the script drops the project path MSBuild appends to each line and turns absolute paths into relative ones. A line that starts with `error` or `warning` matches that message at any location. That's how errors inside generated files are listed, because their line numbers move whenever the generated code does.

After packing a unique local version, run `eng/validate-package.ps1 -Version <version>`. [Validating the package](../../docs/development.md#validating-the-package) explains the script's options. The runner creates one validation folder with the repository's `global.json`, an empty package cache, and one `NuGet.config` for every consumer. Package source mapping in that configuration keeps AnglePlates on `artifacts/package` and the library `PackagedLibrary` packs on the validation folder's feed, and everything else, such as the Native AOT compiler, comes from nuget.org. The runner copies this project there and runs it with the matching `.nupkg` and `.snupkg`, then copies and runs each consumer in its own folder with the same configuration and cache. It stops at the first failure and names the consumer. The Native AOT publish needs the Visual Studio C++ workload on Windows, or clang and the zlib headers on Linux; the script checks for them first and names what's missing. `-SkipNativeAot` skips only the native publish, with a warning. The JIT run and the AOT canary still run, because the canary fails while compiling. A stale package, missing analyzer, manual repository import, unexpected runtime asset, mismatched symbols, or wrong discovery behavior fails validation.
